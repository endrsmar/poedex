Path of Exile · Steam Deck helper · UI options

Two ways to put a price check in front of you without leaving the game

Both mockups are drawn at true Steam Deck proportions (1280×800) and filled with the actual contents of Gladefall's bag, pulled live from the character API. Same backend, same data, two very different amounts of room to work with.

Prices shown are illustrative placeholders for layout purposes, not live quotes. The verdict colors — keep / check / trash — are the real three-state model the pricing layer would emit.

Option A — Decky Loader plugin

Lives in the Quick Access menu

Press the … button and the panel slides in over the running game. 310 px of width is the entire design constraint — everything below is shaped by it.

A

The game keeps running. The QAM does not pause or unfocus PoE — you can read the panel mid-town without dropping your session.

B

Verdict before detail. Bag total and the keep/check/trash split read in under a second. That is the whole point of the tool.

C

The grid mirrors your actual bag. The API returns x/y for every item, so a green cell here is the same slot your cursor needs to find. 12×5 at 22 px per cell fits with room to spare.

D

Controller-native. D-pad moves the focus ring, A opens details. No cursor, no on-screen keyboard, no trackpad.

Option B — Steam overlay browser

A local web app, opened over the game

Same backend serving localhost, viewed through the Steam overlay's built-in browser. Roughly three times the usable area, which buys you a real detail pane — at the cost of a heavier way in.

E

You have to summon it. STEAM button → overlay → browser tab. Slower than the QAM, and the overlay grabs input while it is open.

F

It is a real browser. Plain web app on localhost — you can build and test the entire thing on your Ubuntu machine before the Deck is ever involved.

G

Room for the detail pane. Full mod list plus the comparable listings the price came from, side by side with the grid. The QAM has nowhere to put this.

H

Trackpad-driven. Buttons and links assume a cursor. Workable on the Deck's right pad, but never as clean as D-pad focus.

Where they actually differ

Decky QAM plugin Steam overlay browser
Usable area 310 × 800 px ~1060 × 670 px
Getting to it One button (…) STEAM → overlay → tab
Input D-pad focus, native Trackpad cursor
Game keeps running Yes, unobstructed Yes, but covered and input-grabbed
Detail depth Summary + top items only Full mods, comparables, actions
Dev loop from Ubuntu Deploy to Deck over SSH to test Test entirely in a local browser
Extra dependency Requires Decky Loader installed None

The pragmatic path is both, in this order

They share a backend — the polling service, the pricing engine, and the verdict model are identical, and only the last layer differs. Build the web app first: it runs on your Ubuntu machine today, needs no Deck and no Decky, and lets you get the hard part (rare pricing under rate limits) correct against your real account.

Then wrap the same JSON in a Decky panel. That is the version you will actually use at 2am in handheld mode — one button, D-pad, game still running. The overlay browser stays useful as the place you go when you want the full mod list and the listings behind a price.
